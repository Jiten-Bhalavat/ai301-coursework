# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | The diff's changed files read against the plan's stated scope (in-scope and not-in-scope) and any deviation notes | Every file changed in the diff falls inside the plan's stated boundary OR is covered by a deviation note that explains why. Conversely, every file the plan names as in-scope either appears in the diff OR a deviation note explains why not. Silent additions (files changed but not in plan or deviation) or silent omissions (planned files missing with no note) fail. | required |
| description-matches-diff | The PR description's claims about what the PR does, read against the diff | The description accurately describes what the diff contains. A description claiming "implements the plan exactly" when the diff adds unrequested changes fails. A description claiming to include something the diff lacks fails. Terse descriptions that correctly summarize the fix pass. Descriptions that honestly state what was deferred or out of scope (matching the plan's stated scope) are accurate, not overclaiming. | required |
| test-evidence-decisive | The test-evidence section read against the plan's test plan and the reproduction's steps | The test evidence shows a specific observable before/after that matches the plan's test plan: the reproduction steps re-run with the expected outcome stated and observed. "Tests pass" without showing the specific behavior is not decisive. Evidence exercising an unchanged code path (not the fix) is not decisive. | required |
| repo-checks-run | The test-evidence section for mention of the repo's CI or local test suite | The evidence shows the repo's own checks were run (e.g., `pytest`, `cargo test`, `npm test`, CI status). A PR that never ran the repo's test suite is not ready. If the repo has no test suite or the bundle doesn't mention one, this check passes by default. | required |
| diff-reviewable | The diff and commit list for debris | The diff contains only the fix and directly related changes. No debug prints, no commented-out code, no dead functions, no formatting-only hunks, no unrelated drive-by edits. Commits should have meaningful messages (not just "wip" or "fix"). Minor debris (one commented line) may pass; a diff buried in churn fails. | required |
| template-satisfied | The PR description read against the repo-facts block's stated PR template sections | If the repo has a PR template with required sections (checklist items, changelog entries, issue links), those sections are present and filled with real content, not ignored or left as template placeholders. If no template requirements are stated, this check passes. | required |
| ai-disclosed | The PR description read against the repo-facts block's contribution policy | If the contribution policy requires AI-usage disclosure, the PR description includes a disclosure statement. If the policy is silent or permissive without disclosure requirement, this check passes. Course packages are treated as AI-assisted work. | required |
| deviation-honest | The plan's scope and deviation notes read against the diff and description | Items the plan marks "not in scope" or "deliberately deferred" are NOT deviations - they're planned scope boundaries. Deviation notes (changes from the plan) must match the actual diff. When a description restates the plan's scope boundaries (deferred items, out-of-scope items), that's honest disclosure, not a deviation. This check fails only when the diff or description misrepresents what was actually done. | preferred |

## Verdict rule

Accept if every required check passes. Reject if any required check fails. Preferred checks never change the verdict; they rank accepted packages. Treat `unclear` as `fail` on required checks: a PR you cannot verify from the package is not ready to submit.
