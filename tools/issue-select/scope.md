# Scope: where to look, and who is looking

## Where candidates come from

Only issues in the course's Path Review repository are candidates:

- Repo: `codepath/pathreview-ai301-fa26-s3`

Do not search, fetch, or grade issues from any other repository, however
promising. The wider GitHub comes later in the course; for now the field
is Path Review.

**Path Review house rule.** Path Review is a classroom, and your
classmates are not strangers. Ignore the usual claim signals here: other
students' claim comments (and there may be several on one issue) do not
block an issue, and finding some on the issue you want is normal. Claim
anyway: course credit attaches to the pull request you open, not to
whether it merges, so a shared issue costs nobody anything. Everything
else in the rubric applies as written.

## Your fit profile

I work in Python day to day, mostly building LLM and agent systems:
retrieval pipelines, RAG, prompt and skill authoring, and the FastAPI
services around them. I am comfortable reading someone else's codebase
and working from a failing test backwards to the defect, and I use
pytest regularly.

What I want to get better at is the unglamorous backend craft: input
validation and edge-case handling at library boundaries, and writing
tests that actually pin the behaviour rather than restating it. So rank
retrieval, parsing, and test-correctness issues above everything else,
and rank an issue higher when it names the exact files to touch.

What I want to avoid on a first contribution: frontend and CSS work,
anything that needs infrastructure I cannot run locally, and issues
whose real difficulty is a design argument rather than code.
